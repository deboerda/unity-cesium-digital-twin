# 二维高清插图扩大范围 — 下载并按经纬度铺图

无视觉模型可按本文执行。不要拉伸旧图。

## 目标

大地图（低清）覆盖 lon 97.2–110.5、lat 26.2–34.9。其上叠一层高清插图 `飞行范围插图`。

**现状（须保持贴图与经纬度一致，禁止把旧 JPG 拉大）：**

| | 经度 E | 纬度 N |
|---|---|---|
| 西南 | 103.91916083 | 30.58753045 |
| 东北 | 104.25195738 | 30.75583896 |

对应文件：`Assets/Pictures/飞行范围插图.jpg`  
场景物体：`飞行范围插图`（`HK132.unity`）  
脚本：`Assets/Scripts/MapInsetOverlay.cs`（`LateUpdate` 里用 lon/lat 调 `ConvertToAnchoredPosition` 设 Rect）  
Sprite GUID：`8dbc1595161e8d04498073ab7a86fbb3`（`.meta` 已有，覆盖 jpg 即可，不要换 GUID）

**目标范围（原框再外扩约一圈半，约 2.5 倍原跨度）：**

| | 经度 E | 纬度 N |
|---|---|---|
| 西南 | 103.66956 | 30.46133 |
| 东北 | 104.50156 | 30.88204 |

下载一张覆盖该 bbox 的卫星图，覆盖写入 `飞行范围插图.jpg`，并把 `MapInsetOverlay` / 场景序列化字段改成上表。贴图像素范围必须等于这组经纬度，不能先改 Rect 再用旧图。

## 禁止

- 只改 `sizeDelta` / lon-lat 把旧高清图拉伸。
- 改大地图 `卫星地图_SW97.2_NE110.5.jpg` 或 `GeoMapping.json`。
- 使用 GCJ-02 图源（高德等）直接当 WGS84 铺，会偏约几百米。

## 图源

Esri World Imagery 瓦片（WGS84 / Web Mercator）：

```
https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}
```

备用 host：`https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`

- User-Agent 用浏览器 UA。
- 本机直连 Python `urllib` 常 SSL 超时；**单张** `curl.exe` 直连或走 `http://127.0.0.1:8848` 曾成功（约 15KB JPEG）。
- **并行 curl / 共用 urllib opener 会挂死**；`WaitForExit` 有时杀不掉卡住的 curl，要用轮询 `HasExited` + `Stop-Process`/`taskkill /F`。
- 建议 **zoom=14**（约 38×23=874 张）平衡清晰度与张数；zoom=15 约 76×45=3420 张，本机很难跑完。
- 瓦片缓存目录：`Assets/Pictures/_hd_tile_cache/`，文件名 `{z}_{tx}_{ty}.jpg`。已有少量缓存可续传。
- 清单已生成：`Assets/Pictures/_hd_tile_cache/tiles.txt`（每行：`z tx ty`，当前为 z14）。
- 下载脚本草稿：`Tools/download_hd_tiles.ps1`（需改成可靠超时杀掉 curl）。
- 拼接脚本：`Tools/export_hd_inset.py`（`STEM=飞行范围插图`，bbox 常量须与上表一致，`ZOOM=14`）。

## 推荐步骤

1. 确认一张瓦片能下：  
   `curl.exe --connect-timeout 8 --max-time 15 -A "Mozilla/5.0" -o %TEMP%\t.jpg https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/14/6713/12910`  
   文件应 >800 字节且以 `FF D8` 开头。不通则加 `-x http://127.0.0.1:8848`。
2. **逐张**下载 `tiles.txt`（并发不要超过 1，或最多 2 且必须能强杀子进程）。失败留空或跳过，不要中断整批。
3. 按 `tiles.txt` 的 tx/ty 范围拼成一张图，再按 lon/lat **精确 crop** 到目标 bbox（算法见 `Tools/export_satellite_map.py` 的 `lonlat_to_tile_frac` + crop）。
4. 覆盖保存 `Assets/Pictures/飞行范围插图.jpg`（JPEG，质量约 90）。可写同名 `.json` / `.jgw` 记录范围。
5. 改 `MapInsetOverlay` 默认 lon/lat 与场景 `HK132.unity` 里该组件字段为新 bbox。`Apply()` 会按 `PlaneDisplayController.ConvertToAnchoredPosition` 放进大地图（线性：lon 97.2–110.5 → x ±678.1，lat 26.2–34.9 → y ±388.41）。
6. Unity 导入贴图：Sprite、Max Size **8192**（现 `飞行范围插图.jpg.meta` 已是 8192）。不要改 GUID。
7. 退出 Play 再进，总览视图缩小看整块插图：高清区应明显大于原城市场景框，边缘应对准真实地物，四周不再是把旧城市场景拉糊。

## 验收

- 插图 Rect 的经纬度 = 新图实际覆盖，不是旧图拉伸。
- 相对原框，四周都有**新的**高清地物（不是把原图放大）。
- 飞机/雷达仍按原 `GeoMapping` 落在正确位置（温江一带应对在插图内）。
- 未改大底图与 GeoMapping 窗口。

## 本机已踩坑（可跳过）

- 只改 `MapInsetOverlay` 的 lon/lat 或 `sizeDelta` → 用户截图仍是旧高清块被放大，判定失败。
- Python `ThreadPool` + 全局 `urllib` opener 非线程安全，下完第 1 张就死。
- 多进程/多 curl 打满代理 `127.0.0.1:8848` 会 SSL 超时。
- ArcGIS `MapServer/export?size=8192` 单张大图请求 120s 超时。
- `subprocess.run(timeout=)` / `WaitForExit(ms)` 在本机 Windows 上经常杀不掉卡住的 `curl.exe`。
